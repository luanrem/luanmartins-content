Fixing a typo used to mean a commit in my application repository. That is a
small annoyance, and small annoyances that recur are the ones worth fixing.

## The actual problem

Code and text change at completely different rates. I touch the layout of this
site maybe once a month. I touch the words on it several times a week — a
sharper sentence, a project description that aged badly, a new post.

When both live in the same repository, the fast-moving one drags the slow-moving
one along with it. Every wording fix shows up in the same history as the
component refactors, and every one of them produces a deploy. The history stops
being a record of how the software changed and becomes a record of me editing
prose.

## What I did

The content moved to its own public repository. Three kinds of thing live there
— my work history, the project write-ups, and posts — as markdown, one folder
per item, one file per language.

The site repository never fetches it at runtime. When I merge to `main` in the
content repository, its CI calls a deploy hook, the site builds, and the new
text is live as static HTML. A visitor never touches GitHub. If GitHub is down,
the site does not notice, because GitHub is only involved while the build runs.

## The part I did not expect to matter

The schema.

Because the content sits in its own repository, something has to check it before
it reaches the site — otherwise a missing field becomes a mystery at build time
instead of a red PR. So the frontmatter is validated against a schema, in CI, on
every pull request.

That gate turned out to be worth more than the separation itself. Tags come from
a closed vocabulary, so `nextjs`, `next-js` and `next.js` cannot become three
names for one thing. Every item must exist in English. A post cannot reference a
project that does not exist. None of that depends on me being careful on a busy
day.

## What it costs

Publishing now costs a build — a minute or two before the words are live. I
decided I would rather pay that than have the site quietly depend on an external
service every time someone visits.

And there is a second repository to keep in mind. That is a real cost, and the
thing that makes it bearable is that the boundary is obvious: if it is text, it
goes there; if it renders text, it stays here.
